# 接续、待讨论项与清理

## 接续以当前状态为准

先读项目约定、当前入口、交付文件和接续说明；需要跨会话追溯时读目标会话的实际用户消息和相关结果，不只依据标题或摘要。对报告是否已改好、资料是否已收到、计算或实验是否已执行，用文件或运行证据确认。

在现有接续记录中保留：当前目标和完成情况、最新流程、用户已确定的约束、关键选择及尚未解决的问题、正文／PDF／图源位置、补件状态和重建方式。将失效假设明确标注为历史，避免后续模型把旧笔记当成当前安排。

用户说“先记下来，讨论后再深入”时，更新待讨论项而不是继续扩展文献。每项写清问题、讨论要作的决定、需要的证据类型和重新启动条件。文献已足够支持讨论时如实说明；需要新数据、实验或工程验证的问题可以保留未解，不必把整个调研标成未完成。

## 长任务沟通

开始时用简短目标和完成标准说明范围。有新的科学判断、收到补件、访问阻碍、路线变化或交付进展时及时反馈。按所在环境的反馈频率要求更新；不要只长时间运行工具，让用户猜是否卡住。可以并行的独立工作按可用工具完成，不因等待一份附件停下所有工作。

阶段和最终回复说明当前状态与还差什么；用户或项目有固定状态行时沿用。问题需要用户输入时给完整上下文和具体选择，不重复索要已经提供的信息。

## 清理范围

清理遵守本次授权。处理任务目录中的废弃稿、重复导出、失败下载、一次性迁移脚本和可重建缓存，不自行扩展到全局缓存、其他项目或原始数据。

按实际角色分类，不能只看名字：

| 角色 | 处理方式 |
|---|---|
| 用户原始资料、唯一正文／附件、原始数据、模型或设计原件 | 保留原件；存放错位可有记录地整理 |
| 当前源稿、PDF、图源和证据笔记 | 保留，并检查导航和引用 |
| 重建所需字体、运行库、脚本 | 保留或迁至清楚的依赖位置；不能因位于缓存目录就删除 |
| 已失效稿件、一次性修改脚本、弃用插图 | 确认无当前调用后按授权清理，优先可恢复方式 |
| 页面预览、抽取副本、字节码、失败 HTML | 核对原件与用途后清理；当前验收凭据按任务需要保留 |
| 看似重复的附件 | 比较身份与哈希；不同版本、补充内容和独立原件不能仅按相似文件名合并 |

清理前检索 Markdown、代码和清单中的引用，区分当前依赖与历史记录。删除一个重复图时，将仍有价值的笔记指向保留的来源。对于 ZIP 和解压目录，确认全部成员、附件角色和原始文件保留策略后再决定，不为了腾空间直接删用户提供的压缩包。

## 执行与证据

解析最终绝对路径并确认都在授权目录内，检查重解析点／符号链接，防止递归操作越界。Windows 用同一个 PowerShell 流程和原生路径参数操作，避免枚举路径后拼到另一种 shell 删除。可再生缓存可直接删除；有独特内容的废弃稿优先移入回收站。实际采用的方式写入记录。

记录清理条目、原因、原路径、大小，以及必要的哈希或保留副本位置。检查当前报告、原文和图源的哈希／存在性，确认本地链接和重建依赖仍可用。清理完成报告文件数与实际处理体积；移入回收站的体积不要声称已释放磁盘空间。

不为清理自动制造一套备份目录，不删除有用的研究证据来追求更大的数字。只保留必要的清理记录，避免用大量新文档替代刚移走的临时文件。
